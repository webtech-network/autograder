# Terminal outcomes v1

`autograder.models.contracts.outcome` defines the shared HTTP, Python, and Action
artifact contract. Its JSON Schema is generated by `outcome_json_schema()`;
`validate_outcome()` enforces the additional arithmetic and semantic invariants.
Validation is required before external ingestion and persistence. One terminal
snapshot can be serialized and delivered repeatedly without evaluating again.

The version (`schema_version: "1.0"`) and discriminator (`status`) are required
on the wire. Timestamps require RFC3339 text with offsets; numeric Unix epochs
and date-only strings are rejected. The discriminator is `status`: `completed` requires a finite numeric `score` in
[0, 100], a typed `tree`, and a null `error`; `failed` requires null `score` and
`tree` and a structured error. Booleans and numeric strings are not scores.
Feedback and comparison independently carry `disabled`, `completed`, or `failed`
status. Completed enrichment has content and no error; failed enrichment has an
error and no content. Disabled enrichment has neither. A grading failure cannot
claim completed enrichment.

Every outcome identifies its execution and exact normalized definition through
`execution_id` and `provenance`. Error correlation IDs equal `execution_id`.
`started_at` and `finished_at` have explicit UTC offsets and serialize as UTC;
`duration_ms` is a nonnegative integer measured using a monotonic clock, frozen at
finalization, including engine resource cleanup. It excludes adapter queueing,
persistence, and publication. Internal
pipeline diagnostics are not public result fields.

| Trigger | Grading outcome | Error category / code |
| --- | --- | --- |
| An assessed criterion genuinely scores zero | Completed, score 0 | No top-level error |
| Student compilation/runtime failure or student execution timeout reported by an I/O evaluator | Completed, criterion scores 0 | No top-level error |
| Required preparation file missing | Failed, no score | submission / REQUIRED_FILE_MISSING |
| Preparation command fails because the submission does not satisfy it | Failed, no score | submission / PREPARATION_FAILED |
| Language omitted for a multilingual definition or disallowed language selected | Failed, no score | submission / LANGUAGE_REQUIRED or LANGUAGE_NOT_ALLOWED |
| Required sandbox cannot be provisioned | Failed, no score | capability / CAPABILITY_UNAVAILABLE |
| Sandbox system/transport or artifact extraction failure | Failed, no score | capability / SANDBOX_ERROR |
| Fixture preparation fails | Failed, no score | capability / PREPARATION_ERROR |
| Required structural analysis unavailable | Failed, no score | capability / CAPABILITY_UNAVAILABLE |
| Provider initialization fails | Failed, no score | provider / PROVIDER_UNAVAILABLE |
| Provider request fails | Failed, no score | provider / PROVIDER_ERROR |
| Missing required AI assessment | Failed, no score | provider / MISSING_EVALUATOR_RESULT |
| Duplicate, unknown, or invalid provider assessment | Failed, no score | provider / INVALID_EVALUATOR_RESULT |
| Evaluator returns an invalid numeric grade | Failed, no score | internal / INVALID_EVALUATOR_RESULT |
| Unexpected required step exception | Failed, no score | internal / EXECUTION_ERROR |
| Optional focus or feedback fails | Completed, original grade preserved | feedback.error / FEEDBACK_ERROR |
| Optional comparison fails | Completed, original grade preserved | adapter-supplied comparison.error |
| Persistence/publication fails after finalization | Original artifact remains completed or failed | Adapter delivery failure, outside the grading outcome |

There is no partial grading policy: every configured evaluator is required,
including zero-weight criteria. A required evaluator failure makes the entire
numeric grade unauthoritative. Student timeout is determined by a sandbox's
explicit `TIMEOUT` assessment response; an exception while communicating with
the sandbox is an infrastructure failure. API evaluators assess returned HTTP
status/content; inability to obtain a response is a capability failure. These
conservative classifications avoid claiming that unavailable infrastructure
proved student code incorrect.

Public errors expose stable codes, fixed safe engine messages, categories
(`definition`, `submission`, `capability`, `provider`, `internal`), retryability,
and correlation IDs. Raw exceptions, provider responses, setup stderr, and
internal step names remain in host-controlled diagnostics/logs. Authenticated
external hosts may attest their own safe structured error codes/messages; that
attestation does not prove the local server executed the grade.

The tree has one root representation. Categories retain the base/bonus/penalty
score semantics; holder scores must equal the weighted average of their children
and the root must equal the capped combination of its categories. Base weight is
100. Tests identify their evaluator and globally unique criterion `id`; display
names and grouping are presentation. Serialization rounds scores to two decimal
places, and validation allows only the resulting small arithmetic rounding
error. `outcome_score_vector(completed)` derives an ID-to-score projection from
the authoritative tree. No independently mutable vector is present on the wire.
Comparison's existing `path` field now carries the criterion ID, never a display
path. Tree parameters contain only normalized authoring parameters, never
pipeline-injected resources or prompts. Trusted detail may contain private tests;
student-facing visibility policy belongs to the hosting adapter.

Python terminal models are frozen, including nested JSON maps/lists. Their
`model_dump(mode="json")` output is an independent JSON-compatible delivery
payload. Modifying a payload does not modify the finalized grading snapshot.
Internal mutable `PipelineExecution` and `GradingResult` objects are diagnostic
implementation details, not publisher inputs.

Operationally, v1 outcomes replace legacy duplicate `root`/`tree` and HTTP
`children` wrappers. Stored legacy results are not automatically attested with
current definition hashes. Consumers migrate to the canonical outcome plus
compact polling/history projections; source files and trees require explicit
trusted detail retrieval.


## Publication receipts

The HTTP host writes each finalized outcome to a private, fsynced, atomically
renamed receipt before database publication. Set `WEB_OUTCOME_RECEIPT_DIR` to a
persistent writable directory (default `data/unpublished-outcomes`). Files have
mode 0600. A database failure retains the receipt and leaves the original grade
unchanged. Polling can remain processing until delivery succeeds.

Replay one receipt with the same database configuration:

```sh
python -m web.service.outcome_delivery /path/to/submission-receipt.json
```

Replay validates its bound submission provenance, publishes the existing outcome,
and removes the receipt only after success. Ambiguous commit recovery verifies an
identical persisted outcome; it never runs the pipeline. These receipts preserve
finished grading and do not provide a durable submission scheduler.
